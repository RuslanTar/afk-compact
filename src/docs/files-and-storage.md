Everything the plugin writes, with the default paths. It deletes none of it on its own: see [Pruning old evidence](#pruning-old-evidence).

| `~/.local/state/{{plugin}}/handoffs/<repo>/<ticket-or-topic>/` | Handoff files, with their judged evidence under `evidence/<stem>/`, and under `.staging/` one work folder per handoff run: its draft (kept when refused) and `begin-full.json`, every entry `begin` measured, which a handoff points to when begin's reply left entries out | `/{{plugin}}:handoff`; old evidence deleted, its `MANIFEST.tsv` rows marked `pruned`, only by `prune --apply` ([Pruning old evidence](#pruning-old-evidence)) |

## Subagent copies

Subagent copies may be renamed. When the agent of a subagent copy is not known at save time, the copy is saved as `sub-unknown`. Once a later turn-end check finds the agent in its transcript, the copy gets a new name with `-a<agent id>` (its first 8 characters) in the same folder: the text stays byte for byte the same, the frontmatter gains the agent id and the old name (`renamed_from`), and the old name is removed only after the new file has been checked. A path you noted before the rename still resolves, because both names end in the same id.

## Kept mismatches

The raw summary text handed between hooks (under `pending/`) is removed once a copy holds it. If it differs from the saved copy, and the difference is more than Claude Code's own trailer after the end marker, it is kept as `pending/<id>.post.mismatch.md` or `pending/<id>.mod.mismatch.md`, redacted like a copy, with a `.mismatch.json` beside it that holds only hashes and counts. The plugin deletes none of these. `/{{plugin}}:status` counts them in every session folder, `kept mismatch stashes: <n> (redacted; the plugin never deletes them)`, and lists up to 10 paths. A raw summary that is still unsaved when its session ends is saved at that session's end (under `compact/unattributed/` when its scope cannot be established), or later by another session's hooks, which take that session's lock first.

## The hooks it registers

It registers one mod module and eight classic command hooks: `PreCompact`, `PostCompact`, `SessionStart`, `SessionEnd`, `Stop`, `SubagentStop`, `StopFailure` and `PermissionDenied`.

## File modes and where it never writes

Files are private (folders 0700, files 0600, copies 0400). The private store (`handoff_root`, `log_dir` and `disposable_root`) is never written inside a git work tree (unless that path is git-ignored, which the plugin then logs) or inside a `.planning/` folder, in either mode. A root that is not an absolute path (a relative path, or a Windows drive path such as `C:\x` outside Git Bash's perl, which reads it as `/c/x`) is refused as `root-invalid` and nothing is written under it; `/{{plugin}}:status` shows `root: <key> refused (root-invalid)`. An unset `log_dir` follows `handoff_root` and is refused with it; the logs then go to the default folder. The only thing the plugin writes inside a repository is the repo-mode export described in [Handoffs in git](repo-mode.md#handoffs-in-git-repo-mode), and the three files of `project init`.

## Pruning old evidence

**Nothing is deleted by default.** The plugin removes no handoff, copy, evidence file or log on its own. What grows is evidence: the files a handoff kept in `evidence/<stem>/` beside it, and the dated folders under `disposable_root`. `/{{plugin}}:prune`, or `! "<plugin folder>/scripts/{{plugin}}-store" prune`, lists them and deletes them only after your yes.

- **The list.** A dry run by default: it writes nothing. One line per folder older than the age and at least the size: its age in days, the size it would free, the bucket (`<repo>/<ticket-or-topic>`), the handoff or summary copy it belongs to (or `no handoff file`, `stash copies`) and its path; the 40 largest per root, then a count of the rest (deleted with them, or only listed in a read-only folder; `--all` lists every one), and a total. `--days N` sets the age (default `disposable_keep_days`, or 14 days while that is 0); `--min-mb N` leaves out smaller folders. A folder's age is the date of the handoff or summary copy it belongs to, else that of its newest file. A compaction's folder, named when the compaction starts (`<date>_<time>_<session>-<id>-evidence`), belongs to the summary copy of that session and id, saved a little later (the main one, else the unattributed one).
- **What always stays.** Handoff files and saved summary copies (also a `.md` with `kind: handoff` or `kind: compact-summary` inside an evidence folder), every `MANIFEST.tsv`, a handoff's `ledger.md` and `inflight.md`, links (never followed), and every file a handoff or summary copy newer than the age cites: in a `MANIFEST.tsv` row, or by its path (or a folder above it) in the text, also with a line reference (`run.log:120`, `run.log:120-130`, `app.rb#L12`), in backticks, double or single quotes with spaces, or starting `./evidence/`, `~/` or `$HOME/`. The files an unpublished draft newer than the age kept stay too (its age: its begin date or the newest file in its folder, whichever is later). A newer handoff's own folder, with its restart recipes, is never old enough to be listed. The old folders read while the settings are the defaults (`~/.claude/handoffs`, `~/.claude/trash-staging`) and any folder you add with `--root DIR` are listed apart, read-only: nothing in them is deleted.
- **Deleting.** `--apply` deletes only the files listed, then removes the folders left empty. The dry run prints a `plan:` hash, and `--apply` needs it: `--apply --plan <hash>` refuses (`REFUSED: plan-changed`, nothing deleted) when what it would delete has changed since (a file's path, size or modification time). Before it deletes, it marks the `MANIFEST.tsv` row of each copy it deletes `pruned` (the `scan` column), so `verify` and `/{{plugin}}:resume` report the copy as `pruned`, deleted on purpose, not `missing`, and `restore-evidence` skips it. A file it could not delete gets its row back and is listed as `failed` (exit 3). It refuses to delete while a store folder is refused (for example one inside a git work tree).

Logs, summary copies, drafts under `.staging/` and the old `~/.claude/handoffs` are never pruned; remove them yourself once you no longer need them. The status line's cache state files of sessions that ended more than 7 days ago, or with no recorded end (a crashed session) were not written for 7 days, whatever `--days` says, are listed on a `cache state` line and deleted with the rest.
