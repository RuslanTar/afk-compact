What this version does not do, or has not been run on yet. Each line links to the page with the details.

- **Native Windows** is not supported yet. Without Git for Windows, the plugin's hooks are expected to fail with visible hook errors rather than stay quiet; see [Platforms](compatibility.md#platforms).
- **claude.ai and Cowork** are not tested yet, so for now the plugin is for Claude Code sessions on your own machine.
- **No usable perl** (Alpine without `apk add perl`, a minimal Fedora image without perl, a perl older than 5.28, or one found but unable to start, such as a version manager's shim with no perl picked or one that aborts on a missing library): the hooks print nothing and exit quietly (each leaves one content-free row in the watch folder, in the default one when `handoff_root` is relative and `log_dir` unset, but none when `log_dir` is relative, or the folder or a folder above it holds `.git` or `.planning`, also where a symlink leads: without perl the plugin cannot ask git whether such a folder is ignored), and helper commands answer `REFUSED: helper-runtime`. A hook whose perl ends on a signal (it crashed or was killed) exits the same quiet way and leaves the same row. With a perl that cannot start, helper commands print its error instead; repair or remove that perl. The mod still adds its instructions, but no summary or evidence copies are saved. `/{{plugin}}:handoff` then prints the handoff into the chat, marked as not saved and not secret-scanned.
- **Context windows under about 329K tokens** (with the defaults): plugin compactions, the nudge, the handoff turns and plugin idle compaction are off. Claude Code compacts as usual, and each compaction is still shaped, saved, checked and resumed. See [How the thresholds are clamped](configuration.md#how-the-thresholds-are-clamped).
- **Subagents** get shaped summaries and copies, but no resume block. They also get no nudge and no handoff turn.
- **Headless sessions** (`claude -p`, the Agent SDK, and apps or editors that run Claude Code through it, such as the desktop app): Claude Code rejects a plugin's compaction call there (seen under `claude -p` and the SDK). Instead, at a turn end at or above the target, the plugin runs `/compact` with no arguments and shapes that compaction through its own hook, so the same instructions, saved copy and resume block apply; the resume block goes with your next prompt. It gives no nudge, handoff turn, idle handoff turn or continue there. This path is not yet checked in a live session. When `/compact` cannot run (compaction turned off, or a one-prompt `claude -p` whose input has ended) or fails twice in a row, the plugin stops compacting on its own for the rest of that session. Plugin idle compaction does not run in headless sessions yet. A `/compact` that was skipped (for example by a PreCompact hook) or compacted without the plugin's instructions counts as a failure too: the next try waits for the cooldown and the end of a later turn, never the end of the turn that ran the `/compact`. The transcript shows the plugin's run as a plain `/compact`. Claude Code's own automatic compaction is not affected. `/{{plugin}}:status` says `automatic compaction: by /compact`, or `not available here` once that path is off.
- **Verdicts only inform.** They add a fallback note, a toast, an escalation, or halt mode. They never block or rewrite a compaction.
- **Automatic relaunch covers read-only and allowlisted jobs only.** A production job asks unless `unattended_prod_reads` allows a read-only one, and a job whose output file could not be confirmed asks.
- **Repo mode exports only.** There is no command that accepts a repository for you, and the plugin never stages or commits an export.
- **Handoff turn limits are advice.** The plugin adds notes to tool results and denies nothing, so a model that ignores a note can run past its budget. Native auto-compaction is the backstop.
- **Idle compaction outside the plugin's reach.** Native idle compaction cannot be limited to plugin sessions (Claude Code 2.1.311 has no such setting). Only `"idleCompaction": false` plus this plugin keeps it to them, and only in sessions that read your user `settings.json`: not Cowork, remote or SSH-remote sessions.
- **Five-minute cache the plugin cannot see.** Claude Code can give a subscription session the five-minute cache by a server-side setting the plugin cannot read. In such a session plugin idle compaction reads a cold cache (about the price of coming back to it uncompacted). A cache length you set yourself (`promptCacheTtl`, or Claude Code's cache variables) the plugin does follow.
- **Uncached tail of a compaction.** Claude Code's compaction request, native and plugin idle compaction alike, reads the cache only up to the last summarized reply. Context after it, such as a large batch of tool results that arrived after that reply, is billed as uncached input even when the cache is warm, so such a compaction costs more than the warm-cache estimate under [Idle compaction](idle-compaction.md#idle-compaction). The plugin logs that part as uncovered input (see [Watcher](privacy-and-logs.md#watcher)) and cannot change it.
- **Not yet run live:** the end-to-end runs in a real session, on a machine with managed settings, the handoff turn, the native idle compaction path, the idle handoff turn, plugin idle compaction and its compaction while agents run, the report skill, and the week-long shadow run. The wait helper in a subagent and the seated path under a Team organization have been run live.
